# ALSemby v0.2.0 Local Development Plan

## Release Rule

- Current stable baseline: `v0.1.1`.
- Local release candidate: `v0.2.0`.
- Active branch: `feature/v0.2.0`.
- Do not package, tag, or push Docker images until the user explicitly asks.

## Fixed Scope

These modules are considered stable and should not be reworked unless a bug is found:

- Cover system: manual cover, cover design, auto cover, backup, fonts, templates, translations.
- Real library system: regular RSS real library and JavDB ranking RSS real library.
- Settings center: Emby, notification, proxy, TMDB, account.
- Tool system baseline: RSS real library and Webhook.

## v0.2.0 Direction

Add practical utility value without disturbing the two completed core workflows.

Preferred candidates:

- Emby diagnostics: read-only server capability check, library path visibility, API reachability, image upload preflight hints.
- Local log center: grouped logs for cover, RSS, Webhook, config, and system events.
- Config assistant: detect missing or conflicting settings and explain what still needs to be filled.
- Webhook helper: local payload sample, recent event formatting, and safer enable-state visibility.

Avoid for this cycle:

- 115, STRM transfer, cloud-drive management, or one-stop download workflows.
- Rebuilding the cover generation pipeline.
- Reworking already validated RSS/JavDB hard-link behavior.
- Any NAS/CD2/media scan or Emby write during local development without explicit test instruction.

## Work Order

1. Establish the clean `v0.2.0` branch and baseline checks.
2. Map current frontend/backend module boundaries and remove safe stale local artifacts.
3. Draft the first v0.2.0 feature spec around read-only diagnostics/log visibility.
4. Implement the smallest useful vertical slice.
5. Verify local routes, syntax, and UI behavior.
6. Update `docs/build-log.md` after each development round.

## Current Implementation State

Completed locally on `feature/v0.2.0`:

- Read-only diagnostics helper with local config checks, local file/resource status, recommendations, and an explicit button-only Emby read check.
- Read-only diagnostics helper also validates RSS/automatic-cover Cron expressions and automatic-cover task relationships.
- Read-only log center with category/level/time filters, local log redaction, repeated warning/error hotspots, common error explanations, expandable raw-line details, and recent log entries.
- Read-only config assistant that groups missing or optional settings by Emby, metadata, RSS, cover resources, Webhook, and notification scope.
- Webhook debug helper with safe config checks, recommended events, payload parsing preview, and separated Webhook/task log panels.
- Tool system overview page that aggregates RSS, Webhook, diagnostics, logs, and config assistant cards.
- v0.2.0 version markers, static cache keys, README, changelog, and release checklist are prepared locally.

Still deferred until the user asks:

- Docker packaging, tagging, or pushing a `v0.2.0` image.
- Any new feature that writes to Emby, runs RSS/Webhook/media tasks, scans NAS/CD2/media directories, or manages 115/STRM transfer workflows.
