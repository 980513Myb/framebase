# ALSemby v0.2.0 UI 重构报告

日期：2026-06-05

## 结论

v0.2.0 当前已经完成全站视觉方向统一、核心页面入口重排、工具体系命名统一、关键路由移动端适配检查和 CSS 强覆盖收口。它现在更像一个安静、克制、面向日常维护的 Apple 风格后台工作台，而不是零散功能卡片集合。

`static/style.css` 仍然是单文件样式表，但已从历史叠加式强覆盖阶段收口到少量保护规则阶段。当前剩余 22 处 `!important` 均用于 iOS 输入字号、底部安全距离和封面设计器高度/滚动边界，不再属于“大量覆盖样式”。因此当前状态可以视为“v0.2.0 UI 体系已完成，可进入功能建设和人工体感确认”。

## 1. 设计体系说明

当前设计标准来源于 `#server` 设置页定稿，并沉淀到 `docs/ui-design-system-v0.2.0.md`。

核心原则：

- 黑色/石墨色后台，不做营销页，不做花哨监控墙。
- Apple-blue 只用于选中、焦点、链接、主状态，不再到处铺色。
- 卡片保持功能单元边界，不把整页包成大卡片。
- 底部导航保持悬浮、有边界、磨砂感，不再压出大黑框。
- 页面主体使用固定工作区和内部滚动，减少文档级无限拉长。
- 空状态保持小而明确，不再使用彩色长方体、装饰插画或巨大空白。

## 2. 修改页面列表

已统一的核心页面：

- `#dashboard`：主页从装饰入口改为工作台概览。
- `#manual`：保留封面工作台结构，完成底部栏遮挡修复和视觉统一检查。
- `#auto`：自动封面页纳入统一滚动与卡片体系。
- `#rss`：RSS 真实库保留路径覆盖逻辑，任务卡片恢复桌面双列、移动单列。
- `#webhook`：配置区、状态区、本地记录、调试区统一成同一视觉语言。
- `#logs`：日志从工具中独立出来，成为底部导航一级入口。
- `#tools`：从大工具看板改回兼容/说明页，实际工具入口由底部弹出菜单承载，并按核心系统、问题清单、辅助检查分组。
- `#server`：作为设置页视觉基准，保持 980px 单卡配置中心。
- `#media_maintenance`：命名统一为 `媒体问题清单`，并区分严重问题、建议处理、信息标签和基础完整条目。
- `#collections`：命名统一为 `合集问题清单`，并按空合集、成员过少、缺封面、缺简介、缺 TMDb 等问题建立严重度、筛选和 CSV 导出。
- `#emby_tasks`：命名统一为 `Emby 任务中心`，按 Emby 原生计划任务分组展示，并单独凸显 `神医助手` 分区。

## 3. CSS 重构内容

已完成：

- 建立了 v0.2.0 设计系统文档，明确颜色、卡片、按钮、表单、日志、工具入口和移动端规则。
- 将设置页新规则限定到 `.server-page-shell`，避免 `.server-grid-layout` 影响 RSS 等共享布局。
- 为主页、RSS、Webhook、日志弹窗、工具入口增加了页面级收口规则。
- 更新样式缓存 key 为 `alsemby-apple-20260605ar`，并更新脚本缓存 key 为 `alsemby-v0.2.0-ui20260605f`，避免浏览器加载旧 CSS/JS。

收口结果：

- `static/style.css` 仍是单文件历史叠加结构。
- 当前仍有 22 处 `!important`，但它们已经从“历史强覆盖”缩小为“保护性例外”：iOS 输入字号、滚动页底部安全距离、封面设计器高度/滚动边界。
- 已将旧移动端兜底块重新归类为 `Legacy mobile adaptation pass`，避免继续把移动端强覆盖误算到确认弹窗模块。
- 已将旧响应式布局兜底块重新归类为 `Legacy responsive layout pass`，并移除了其中的非必要强覆盖。
- 已从当前 Apple 设计层中移除卡片、悬浮态、Toast、Confirm 等可由正常级联承接的强覆盖。
- 已从旧 premium 视觉层中移除不再需要的背景、状态、旧卡片、旧弹窗、旧按钮和旧 Toast 强覆盖；手动封面结构规则保留，避免破坏设计器布局。
- 已从旧全局表单规则中移除非必要强覆盖，并让最终底部 Dock 视觉层通过正常级联生效；手动封面结构保护、旧移动端兜底和浮动边界保护暂时保留。
- 已将 `Emby 任务中心`、`媒体问题清单`、`合集问题清单` 新增的 preflight / safety / blueprint / read-banner 样式收成共享组件规则，减少新功能继续制造页面专属重复 CSS。
- 已将日志快捷窗最终样式、通用按钮背景、主背景、卡片背景和空状态背景中的一批低风险强覆盖转回正常级联；手动封面结构保护、底部 Dock 边界保护、移动端兜底和装饰伪元素隐藏规则暂时保留，避免回归旧黑框、遮挡和长方体装饰问题。
- 已从旧移动端兜底中移除卡片、通用 modal、日志快捷窗、服务器网格和资源网格的非必要强覆盖，让后置的 v0.2.0 组件层能正常接管；iOS 输入字号、手动封面移动布局和底部导航边界仍保留强覆盖保护。
- 已从旧移动端首页/海报墙兜底中移除 dashboard 布局、poster wall、wall track、wall item 和移动端滚动动画的非必要强覆盖，让后置 `Dashboard workbench standard pass` 接管移动端工作台宽度、间距和海报墙高度；`Apple workspace height refinement` 暂不降级，因为它仍在保护手动封面设计器不被旧桌面布局重新拉伸。
- 已从旧移动端 Toast 位置兜底中移除非必要强覆盖，让后置 v0.2.0 Toast 规则接管最终位置；确认框移动端尺寸已交给统一 Confirm 层接管。
- 已继续降级旧移动端 `.scroll-view` 额外兜底和最终 Toast 移动端定位强覆盖；底部 Dock 边界保护仍保留，避免黑框/遮挡问题回归。
- 已移除旧移动端确认弹窗尺寸兜底，让后置统一 Confirm 层接管最终宽度与内边距；确认框交互仍通过只打开/取消方式验证，不触发实际连接请求。
- 已将任务日志浮窗的移动端宽度、左右边距和高度兜底从强覆盖降级为普通移动端规则；浮窗仍保留移动端不溢出保护，但不再压住后续组件层。
- 已从 Apple 产品设计层继续降级 disabled 按钮、装饰伪元素隐藏和移动端普通 padding 的低风险强覆盖；移动端 `scroll-view` 的底部安全距离仍保留强覆盖，避免底部 Dock 遮挡。
- 已将设置页壳宽度、RSS 表单强调边框、手动/自定义封面应用按钮和工具说明卡片间距从强覆盖降级为普通组件规则；这些选择器由更具体的页面层或后置组件层接管，未触碰 Dock、设计器结构和真实任务行为。
- 已继续降级早期封面设计器桌面结构和控件皮肤强覆盖，让后置 Apple 设计层和移动端单列规则恢复接管；同时修复 390px 移动端 `#manual` / `#custom` 预览画布被压到 2px 的问题，当前移动端画布恢复到 324px 宽且无横向溢出。
- 已将底部 Dock 外壳和导航主体的定位、尺寸、背景、指针事件、伪元素隐藏等强覆盖降级为普通级联规则，同时保留滚动区底部安全距离和封面设计器移动端保护，避免内容再次被底部栏遮挡。
- 已将旧移动端基础透明层、旧 Dock 透明兜底、早期移动端封面设计器结构规则从强覆盖降级为普通规则，并在后置 Apple 封面设计层补充移动端单列规则，让正常级联接管这些页面结构。
- 已在 `static/style.css` 顶部补充 v0.2.0 CSS 架构索引，明确 `Layer 1 - Base Tokens`、`Layer 2 - Shared Components`、`Layer 3 - Page Rollouts` 三层边界，并标注后续新增 UI 应进入 v0.2.0 层而不是追加宽泛覆盖。
- 当前剩余强覆盖主要用于 iOS 输入字号保护、滚动页底部安全距离、封面设计器高度/滚动边界，暂不继续硬删，避免底部遮挡和封面设计器移动端回归。
- 这部分不再阻塞 v0.2.0 UI 体系验收；后续如果要继续拆 CSS，可作为 v0.2.x 的架构优化单独处理。

## 4. 组件统一内容

已统一方向：

- 卡片：石墨底、细边框、轻顶部高光、低阴影。
- 按钮：主按钮、次按钮、图标按钮、危险按钮在视觉上更接近统一。
- 表单：设置页与工具页输入框、选择框、只读框使用同一暗色嵌入风格。
- 弹窗：日志中心弹窗和确认弹窗的暗色磨砂方向已统一。
- 确认弹窗：`测试 Emby 连接` 的确认框已完成只打开/取消验证，取消后遮罩正常关闭，不触发实际连接请求。
- Badge / 状态：成功、警告、错误、只读状态使用更克制的色彩。
- 空状态：主页、RSS、Webhook、工具页减少了大面积装饰。

可继续优化但不阻塞 v0.2.0：

- 部分旧组件仍靠旧类名和后置覆盖协作，不是纯净组件层。
- `modal`、`drawer`、`button`、`card` 还可以继续抽成更明确的通用类。

当前结构：

## 6. 移动端适配结果

已通过只读浏览器检查：

- 390px 移动宽度下，`#dashboard`、`#manual`、`#auto`、`#rss`、`#webhook`、`#logs`、`#tools`、`#server`、`#settings`、`#account`、`#media_maintenance`、`#collections`、`#emby_tasks` 未发现横向溢出。
- 底部导航保持浮动边界，不再形成巨大黑框。
- RSS、设置表单、Webhook、日志中心在移动端均保持单列或可滚动结构。

注意：

- 移动端检查没有执行 Emby 读取、RSS 运行、Webhook 触发、封面生成或媒体扫描。

## 7. 后续优化建议

优先级建议：

1. 后续 CSS 组件化。
   - 当前 22 个 `!important` 是保护性例外，不建议为了数字继续硬删。
   - 下一步若要做代码洁癖，可把 `static/style.css` 拆成 tokens / components / pages 三层文件，而不是继续堆后置覆盖。

2. 继续观察 `媒体问题清单` 的真实数据表现。
   - 当前已能清楚区分严重问题、建议处理、信息标签和基础完整。
   - 下一步只需要在真实读取后确认 Emby 返回字段是否覆盖所有路径异常场景。

3. 观察 `合集问题清单` 的真实数据表现。
   - 当前已能清楚回答：哪些合集为空、缺封面、缺简介、缺 TMDb、成员过少。
   - 下一步只需要在真实读取后确认 Emby 返回的 `RecursiveItemCount` / `ChildCount` 是否覆盖所有合集成员数场景。

4. 继续完善 `Emby 任务中心`。
   - 当前已具备分类筛选、结果筛选、失败统计和日志跳转。
   - 下一步可在真实任务读取后继续观察失败状态字段是否覆盖所有 Emby 返回情况。

5. 暂不建议再添加新的诊断类页面。
   - v0.2.0 的下一步价值应该来自真实工具能力，而不是更多说明/检查卡片。
